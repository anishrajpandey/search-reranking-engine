Engine Architecture & FAQs
What is Real-Time Search Re-Ranking?
Traditional e-commerce search relies on static BM25 or offline batch model scores that update once every few days. Real-time re-ranking listens to live user interaction streams (clicks, dwell times, conversions) to dynamically re-score search candidate lists in sub-milliseconds without waiting for offline model retraining.
How does Inverse Propensity Scoring (IPS) work?
Users disproportionately click top search results due to position bias, regardless of relevancy. Inverse Propensity Scoring corrects for this by assigning inverse rank weights w(k) = 1 / √k. A click on rank #3 yields a higher positive propensity signal than a click on rank #1, ensuring fair item discovery.
What technology stack powers this real-time pipeline?
The pipeline streams click payloads into an Apache Kafka event topic. A Python Stream Processor consumes events, calculates propensity weights, and writes updated document scores directly to Redis Sorted Sets (ZSETs), served via a high-performance FastAPI Gateway.
Why is serving latency sub-2 milliseconds?
Redis Sorted Sets store key-value score maps entirely in-memory with O(log N + M) lookup time. Re-ranking queries query Redis ZSETs directly in RAM, achieving sub-2ms round-trip latency without touching disk or executing heavy inference models.
